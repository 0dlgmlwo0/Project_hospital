## 🔧 각 파일 기능 요약

| 패키지 | 클래스 | 설명 |
|--------|--------|------|
| async | MedicalSubjectAsyncRunner | 진료과목 데이터를 비동기 처리 및 저장 |
| async | ProDocAsyncRunner | 전문의 데이터를 비동기 처리 및 저장 |
| client | MedicalSubjectApiCaller | 진료과목 API 호출 및 응답(JSON → 객체) 변환 |
| client | ProDocApiCaller | 전문의 API 호출 및 응답(JSON → 객체) 변환 |
| controller | MedicalSubjectController | 진료과목 저장 및 상태 조회 API 엔드포인트 |
| controller | ProDocController | 전문의 저장 및 상태 조회 API 엔드포인트 |
| dto.api | MedicalSubjectApiResponse | 진료과목 API 응답 구조 매핑 클래스 |
| dto.api | ProDocApiResponse | 전문의 API 응답 구조 매핑 클래스 |
| entity | MedicalSubject | 진료과목 DB Entity |
| entity | ProDoc | 전문의 DB Entity |
| parser | MedicalSubjectApiParser | 진료과목 API 데이터 파싱 및 정규화 |
| parser | ProDocApiParser | 전문의 API 데이터 파싱 및 정규화 |
| repository | MedicalSubjectRepository | 진료과목 저장용 JPA |
| repository | ProDocRepository | 전문의 저장용 JPA |
| service | MedicalSubjectService | 진료과목 비즈니스 로직 담당 |
| service | ProDocService | 전문의 비즈니스 로직 담당 |
| service | HospitalCodeFetcher | 병원코드 목록 조회 |

## 🔄 전체 흐름도 (Mermaid)

```mermaid
flowchart TD
    C1[Client 요청 (/api/subject/save 또는 /api/prodoc/save)]
    C1 --> Controller

    Controller --> Service
    Service --> HospitalCodeFetcher
    HospitalCodeFetcher -->|List<String>| AsyncRunner

    subgraph AsyncRunner
        A1[병원코드 1개당 → callApi()] --> A2[응답 JSON → DTO 변환]
        A2 --> A3[Parser 통해 정규화된 객체 생성]
        A3 --> A4[기존 데이터 삭제 후 → saveAll()]
    end

    AsyncRunner --> Repository
    Repository --> DB[(DB 저장)]
```

## 📝 비고

- `@Async` 사용 시 병렬 실행을 위해 `AsyncConfig` 에서 `ThreadPoolTaskExecutor` 설정 필요
- 병원코드 기반 반복 호출이므로 병원 수가 많을 경우 API 과부하 주의
- `/status` API 로 실시간 처리현황 확인 가능
